06 · WHY TOKENTA SIGNAL · 339

Perplexity给搜索装上时光机，最多倒回365天

11月25日，Perplexity推出Time Machine，搜索与上下文API加一个时间截点，回看一年前的网页快照。价格不变，专为评测模型预测能力而设。

实时网络什么都知道，恰恰是它没法用来考预测能力的原因。

// SIGNAL 339 · EXECUTIVE BRIEF

预测评测长期被一个漏洞拖着，模型可能只是在背答案。时间截点把这个漏洞堵上了，往后谁声称自己的模型会预测，先问它敢不敢在截断的网上考。

CASE STUDY / 案例分析

做法并不复杂。Perplexity每次爬页面都会存一份带时间戳的副本，同一个URL攒出版本历史。请求里加一个snapshot_as_of，检索只考虑截点之前发布或首次抓到的页面，再把每个候选换成截点前最新的存档版本，排名按旧文本算。时间戳用RFC 3339格式带时区，未来的截点与超出窗口的请求会被拒绝。

例子是Perplexity自己给的。搜python.org，截点设在2026年10月20日，返回的是当天的页面。上下文API读同一页，列出的最新版是Python 3.15.0，而不是今天页面上的更新版本。调用方式没变，老的API密钥直接能用，不用换接口，也不用重新配置。

训练环节的数据更实在。训完之后再用Time Machine考，得分涨到0.80，超过了市场价对应的0.79。用实时网训练，约九成训练组梯度为零，等于白练。Epochal前一天刚推出类似的Time Portal，两家撞期，说明时间截点正在变成搜索API的标配功能。

01 / WHAT TO WATCH

自测数字漂亮，第三方还没验过

Perplexity还请自动裁判逐页检查截点之后的信息，三组里被标记的页面都不到0.5%，随机样本里是0.25%，对照组Exa是1.10%。数字是自己测的，裁判也是自己的，方法与原始数据都没公开，独立核验还没出现。

另一个没公开的是覆盖率。存档只含爬过的页面，冷门网址在某个截点可能根本没有副本。拿它做严肃评测之前，先抽查自己领域的页面在目标日期有没有存档。

02 / WHY IT MATTERS

泄题的漏洞堵上了，评测的生意变了

预测能力一直是模型评测里最难服众的一项，分数高可能是记性好。时间截点给了出题人一把尺子，往后发布预测基准，先问一句截点设在哪。

对开发者来说，真正的变化在训练环节。历史快照让模型可以在过去的问题上练预测，再拿后来发生的事打分，训练数据第一次有了干净的时间边界。

// DETERMINISTIC EXECUTION PIPELINE

01 / THE LAUNCH

11月25日，Perplexity推出Time Machine，给搜索API与上下文API加了一个时间截点。

02 / THE MECHANISM

每次爬取都存一份带时间戳的副本，请求带上snapshot_as_of，只返回截点之前的版本。

03 / THE USE

评测时把截点设在提问当天，模型只能看到当时已有的信息，没法抄后来的答案。

04 / THE PROOF

训练前，模型用实时网在留出问题上得分0.94，用Time Machine只有0.77，差距就是泄题的水分。

03 / PARADIGM SHIFT

从考记忆，到考预测

FROM MEMORY TO FORECAST

从考记忆，到考预测

实时网让评测分不清模型是真会预测还是背下了答案，时间截点把两种能力分开了。

FROM REVIEW TO CUTOFF

从事后复盘，到事前设限

以前靠人工剔除泄题的题目，现在截点在请求层面就拦住了后来的信息，公平性由参数保证。

BOUNDARY / 边界与工程约束

Time Machine只面向搜索API与上下文API，不改变普通Perplexity应用。存档只覆盖Perplexity自己爬过的页面，冷门网址在目标日期可能没有副本。自测的日期覆盖率与得分对比未经独立核验，Epochal的Time Portal是同类竞品。
