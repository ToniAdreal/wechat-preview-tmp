1PASSWORD BREACH

03 · WHY TOKENTA SIGNAL · 336

员工GitHub账号被盗，1Password丢了客户资料

11月25日，1Password 披露后端入侵。攻击者经员工 GitHub 账号植入恶意代码，拿走部分客户的姓名与邮箱，保险库与密钥没有被碰。

密码管理器被攻破，丢的不是密码，是装密码的抽屉边上的名片。

// SIGNAL 336 · EXECUTIVE BRIEF

Tokenta Signal判断：1Password 这次丢的是账户边的行政资料，保险库没被碰，零知识设计接住了最坏的情况，真正的后患是拿走的姓名与邮箱会变成钓鱼邮件的弹药。

CASE STUDY / 案例分析

时间线很短。11 月 19 日，1Password 发现有迹象表明攻击者进入了一名员工的公司 GitHub 账号，随即开始调查。6 天后，公司公开披露，攻击者用这个账号读到私有源码，向后端服务植入恶意代码，恶意代码下载了部分客户的账户记录，还进了持续集成与持续交付系统。

被拿走的东西分两类。一类是客户账户记录，姓名、邮箱、账户与用户标识、建号与最后登录时间、公钥、安全远程密码协议参数，以及邀请、开通与账户恢复邮件里的令牌。另一类是公司自己的东西，私有仓库的源码与构建系统里的基础设施凭证，1Password 说源码里没有客户机密，已经把可能暴露的凭证全部轮换。

没有被碰的东西同样重要。保险库与里面的条目、保护保险库的密钥、账户恢复密钥、应用与浏览器扩展都不在受影响之列。1Password 不保存用户的账户密码与密钥，加密密钥只在用户手里，这是保险库没有被打开的直接原因。

01 / WHAT TO WATCH

被盗的令牌不能单独开门

邀请与恢复邮件里的令牌单独用不了。完成邀请或恢复还要过单点登录，或者输入发到注册邮箱的 6 位验证码。1Password 说没有发现有人用这些令牌接管账户的证据。

公司还是把验证码从 6 位数字改成了 10 位字母数字组合，理由是让暴力猜测基本不可能。这个改动是预防性的，不是发现了新的利用方式。

02 / WHY IT MATTERS

真正的后患在收件箱里

姓名加邮箱是最适合钓鱼的组合。接下来几周，冒充 1Password 的邀请与恢复邮件很可能变多，1Password 在公告里专门提醒，用户只在自己打开的应用或亲手输入的官网地址里输入密码与密钥。

受影响的客户人数至今没有公布。1Password 说正在逐一通知相关客户，根本原因分析要等完整调查结束，未来几周内发布。人数与入侵手法这两个关键问题，目前都没有答案。

// DETERMINISTIC EXECUTION PIPELINE

01 / THE ENTRY

攻击者拿到一名员工的公司 GitHub 账号，1Password 没有说明这个账号是怎么被拿到的。

02 / THE SPREAD

攻击者用这个账号读到私有源码，并向后端服务植入恶意代码，代码随后下载了客户账户记录。

03 / THE TAKE

被拿走的是部分客户的姓名、邮箱、账户标识、建号与最后登录时间，以及公钥与协议参数。

04 / THE RESPONSE

1Password 停用账号、吊销被盗令牌、轮换可能暴露的凭证，并请来独立安全专家验证整改。

03 / PARADIGM SHIFT

从保密码，到保名片

FROM PROTECTING PASSWORDS TO PROTECTING CONTACT DETAILS

从保密码，到保名片

保险库有零知识设计护着，攻击者转而拿走了保险库之外的账户资料，姓名与邮箱成了新的战利品。

FROM CODE REPOSITORY TO BACKEND SERVICES

从代码仓库，到后端服务

一个员工的 GitHub 账号成了跳板，源码、构建系统与后端服务连成了一条入侵链，开发环节的安全成了整条防线的短板。

BOUNDARY / 边界与工程约束

受影响客户的具体人数没有公布，攻击者如何拿到员工 GitHub 账号也没有说明。根本原因分析还在调查中，未来几周发布。保险库未受影响的说法来自 1Password 自己的披露与零知识设计，独立专家的验证结果尚未公开。

TOKENTA SIGNAL JUDGMENT

零知识设计这一次接住了攻击

Tokenta Signal判断：1Password 这次丢的是账户边的行政资料，保险库没被碰，零知识设计接住了最坏的情况，真正的后患是拿走的姓名与邮箱会变成钓鱼邮件的弹药。
