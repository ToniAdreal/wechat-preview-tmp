MICROSOFT × AMD HELIOS

03 · WHY TOKENTA SIGNAL · 320

微软点亮首柜 AMD Helios，Azure 实验室先跑推理验证

11月23日，AMD 宣布微软已点亮首柜 Helios 机架式 AI 系统，正在 Azure 实验室里跑早期推理负载验证。这套系统面向 Azure 大规模部署，整柜算力先在实验室里过关，再谈上云。

机柜通电只是第一步，能不能在云厂商的实验室里稳定跑起来，才决定它有没有资格进数据中心。

// SIGNAL 320 · EXECUTIVE BRIEF

Tokenta Signal判断：Helios 进 Azure 的关键一步，是微软把它点亮并跑起早期负载。

CASE STUDY / 案例分析

Helios 把整柜当成产品交到云厂商手里。云厂商不用自己攒机柜，整柜到手就能点亮验证。微软今年秋季收货，11月23日点亮，实验室里的这套系统要先证明整柜思路跑得通。

微软技术博客给出机柜配置。单柜装 72 张 MI455X，配 18 颗 EPYC Venice 处理器，显存总量 31TB。机柜液冷，两层以太网把机柜连成更大集群。这套配置为推理而生，瞄准长上下文推理，搜索与多智能体服务。

双方的合作框架定在今年 7 月，目标是在 Azure 大规模部署 Helios。AMD 说 Azure 有望成为最早用 Helios 跑推理的云厂商之一。部署规模，商用时间与定价都没公布，实验室验证是眼下唯一能看到的进度。

01 / WHY IT MATTERS

验证要过几道关，烧机是最后一道

微软技术博客写清了从点亮到上线的流程。先是打地基，系统稳定启动，设备能被发现，健康状态能上报。再跑微基准，测算力，显存带宽与卡间传输，摸清加速器之间怎么通信。

最后是烧机，整批机柜在数据中心里长时间跑持续负载。跑得久才能撞见偶发故障，散热问题与平时测不出的异常。修好再复测，通过后再进隔离柜验证，合格的节点才能当备件回生产环境。

02 / WHAT TO WATCH

实验室里的柜子，离生产环境还有几步

眼下只有一个机柜在实验室里跑早期负载。商用上线时间，定价与部署规模都没公布，独立实测成绩也没有。单柜跑通不等于集群跑通，机柜之间的网络与整套软件还要在更大规模下再验一遍。

对 AMD 来说，Azure 的验证进度就是 Helios 的进度表。验证顺利，Helios 才能从实验室走向 Azure 的推理服务。验证拖下去，部署时间表也要跟着往后挪。
