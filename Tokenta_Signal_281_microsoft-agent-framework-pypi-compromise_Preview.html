微软官方包里藏了窃密器，装上就跑

微软官方 Python 包 agent-framework 的 1.26.1 与 1.26.2 两个版本 11 月 17 日被传上 PyPI，内藏凭据窃密器，随每次 Python 启动运行。攻击者疑似盗用了微软发布流水线的证书与私钥。

防投毒到最后，防的是发布流水线本身。

// SIGNAL 281 · EXECUTIVE BRIEF

供应链攻击最狠的一招不是藏得多深，是借官方账号发出来。证书一丢，签名本身就成了伪装。

CASE STUDY / 案例分析

2026 年 11 月 17 日 20 时 35 分 UTC，一个恶意版 agent-framework 1.26.1 被传上 PyPI。33 分钟后，1.26.2 跟着上线。21 时 30 分左右，两版都被下架。整个窗口大约一小时，包每周下载约 4.1 万次。

恶意代码的藏身处是一个 .pth 文件。Python 每次启动都会执行 .pth 文件里的导入行，不管用户有没有导入 agent-framework。窃密器一跑就去翻环境变量、凭据文件、其他进程的环境，还去要 Azure 托管身份令牌与 Azure DevOps、GitHub Actions 的 OIDC 令牌。偷来的东西压成一个 JSON 文档，发到攻击者控制的 webhook.site 地址。

Wiz 的分析指向一个更麻烦的源头，攻击者疑似盗用了微软 ESRP 发布流水线的客户端证书与私钥。ESRP 是微软内部用来签名与发布这个包的服务。证书一丢，恶意版就是从微软官方发布账号发出来的，看起来和正常更新没有区别。攻击者的工具自称 Cairn，一个开源 AI 渗透测试框架。

01 / WHAT TO WATCH

第二版是冲着比对来的

1.26.2 的设计明显是为了躲比对。它的包初始化文件与干净版 1.26.0 逐字节一致，恶意代码挪到了新模块 af_runtime_diag.py 里。只比对第一版的人，会以为第二版干净了。

两版都保留了对合法 agent-framework-core 1.26.0 的依赖，框架本身照常工作，窃密器在后台跑。用户什么都感觉不到，这是供应链投毒最难防的一处。

02 / WHY IT MATTERS

签名本身成了伪装

8 家安全公司几乎同时发现了这次投毒，Wiz、Socket、StepSecurity、Endor Labs、OX Security 都出了分析。PyPI 的隔离动作很快，但装上的人已经装上了。

这是今年第二个微软相关 PyPI 包被攻陷。官方建议很直接，锁定 1.26.0，从干净环境重建，轮换所有可能被触及的凭据。

03 / PARADIGM SHIFT

从防恶意包，到防发布流水线

FROM BLOCKING BAD PACKAGES TO GUARDING THE PIPELINE

从防恶意包，到防发布流水线

这次投毒没有伪造账号，没有钓鱼链接，恶意版就是从微软官方发布账号发出来的。防线要从包本身，前移到签发签名的流水线。

FROM RUN ON IMPORT TO RUN ON STARTUP

从导入才跑，到启动就跑

.pth 文件随每次 Python 启动运行，装上就跑，不导入包也跑。传统的装后检查思路，在这种钩子面前慢了一拍。
