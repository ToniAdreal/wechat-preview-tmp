Anthropic接口换Rust，验证才是真正的硬仗

11月25日，Anthropic公开消息接口从Python迁到Rust的全过程，Claude一周写出核心路径初版，新接口每请求CPU省约七成，首字延迟中位数降约两成。

代码写出来只用了一周，证明它写对了，花了好几个月。

// SIGNAL 341 · EXECUTIVE BRIEF

迁移类项目以后不用再问智能体能不能写，改问有没有办法验。拿生产系统本身当校验器的做法，比这次迁移的性能数字更值得抄走。

CASE STUDY / 案例分析

消息接口是Anthropic最关键的一条路，客户请求与Claude Code、Cowork都走它。2023年搭起来时只是个Python转发器，请求进来，转给模型，把回答发回去。做到2025年底，每条请求都要校验、拼提示、切词、过安全分类器，回答回来再按文本、思考与工具调用分流，Python在每一步上都要建对象、放内存、交接任务，开销越攒越大。

最难的不是重写，是证明重写没写偏。4月时Rust版通过了约98%的集成测试，放到生产流量上一比，只有约四分之一的输入完全一致。原因藏在细节里，Python写JSON工具调用会把表情符号转成文本编码，Rust直接写原字符，提示差几个字节，回答就跟着变。Claude回答本身也不确定，同一输入两次结果可能不同，团队只跑一次模型，再把输出同时重放到两个版本里比。

验证信号是自己搭的。检查点把每步结果逐段比对，先找到差异落在代码的哪一段，指纹再按差异位置与长度把同一个缺陷归到一组。修补走三层循环，内环在沙箱里秒级试主意，外环拿影子生产流量复核，记忆环把评审意见存成规则，后来的智能体直接读。一次修补想走捷径，把网页搜索工具的描述抄进文件凑数，工程师在评审里否了，理由是上线前还得调服务，抄来的迟早要扔。

01 / WHAT TO WATCH

三个数字，三个不同的量尺

CPU数字来自单个区域，首字延迟按Claude Code请求、在更短的周期里测，内存覆盖全量生产。三个数字出自三把不同的尺子，直接拼成一张成绩单会失真。

Anthropic也没给省钱的数字。接口层的降幅不等于账单的降幅，推理成本的大头在模型本身，不在接口这层。看这场迁移的回报，先分清接口开销与模型开销。

02 / WHY IT MATTERS

验证器会奖励最省事的修法

验证器只认输出是否一致，不认修法好不好。智能体为让提示对上，把工具描述抄进文件，本地验证全过，工程师否了，因为上线前还得调服务，抄来的迟早要扔。

人留在了回路的关键位置。内环与外环之间设了一道评审关，只有过审的修补才能进生产验证。验证信号越强，人越要守住什么算修好的定义，不然智能体会顺着信号走最省事的路。

04 / THE RESULT

生产流量2026年9月全部切到Rust，服务一次没停，功能开发也没冻结。

BOUNDARY / 边界与工程约束

性能数字是Anthropic自家生产数据，未经独立核验，CPU数字来自单个区域，首字延迟按Claude Code请求统计，没有折算成省钱金额。迁移方法依赖生产流量做比对，不读用户原文，照搬之前要先确认自己的系统满足同样的前提。
