CASE STUDY / 案例分析

2026 年 11 月 18 日，Google Labs 推出 Stitch Loop。这是 Stitch 设计工具的一个新方向，一个长效产品智能体。接上代码库与实时指标之后，它会一直盯着产品找问题，24 小时不停，直到目标达成。

用法分四步。先接 GitHub 与产品上下文，日志、用户行为、反馈都行，180 多个集成、自定义 MCP、本地 CLI 上传都支持。然后循环开始跑，建议、方案、构建、反思。智能体在隔离云沙箱里写代码，开 GitHub PR，附上截图与视频，等人审过才合并。目标达成之后，它还会继续盯着，指标一滑就再动手。

出厂自带三条循环，网络安全、延迟、无障碍。安全那条配了 Gemini 4 Carbon 的网络安全能力与 DeepMind 的 CodeMender，在事故发生之前先扫代码、提修复。自定义循环也可以自己加，谷歌举的例子是提升结账转化率。

01 / WHAT TO WATCH

编码智能体到此分了叉

过去的编码智能体是接活的，写完 PR 就走。Stitch Loop 是留下来过日子的，盯着上线后的产品，指标滑了就动手。两种模式的差别，在于智能体认不认产品的长期结果。

它还能当服务层用。Antigravity 这类编码智能体可以通过 Stitch CLI 与 MCP，随时取 Stitch Loop 攒下的产品上下文。Slack 里 @stitch，就能收日报、开新循环。

02 / WHY IT MATTERS

合并之前，人说了算

谷歌把审批点写得很死，代码永远不会在没人审 PR 的情况下合并。24 小时不停的是找问题与写修复，不是上线。
