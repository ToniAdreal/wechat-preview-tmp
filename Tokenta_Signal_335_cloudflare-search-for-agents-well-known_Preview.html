CLOUDFLARE

02 · WHY TOKENTA SIGNAL · 335

网站给智能体留了个搜索口，Cloudflare一键开通

11月25日，Cloudflare 推出 Search for Agents。站长打开一个开关，网站就有了智能体能发现的搜索接口，返回原文片段，不代答。

智能体不用再一页一页爬你的网站，网站自己递上了目录。

// SIGNAL 335 · EXECUTIVE BRIEF

Tokenta Signal判断：Cloudflare 把智能体搜索做成一个开关，网站向智能体开放的第一步从搭系统变成了点开关。

CASE STUDY / 案例分析

发现机制是这套东西的关键。Cloudflare 会在网站每个 HTML 页面的 head 里加四组元标签，写明搜索接口的地址、用法与文档链接。开了 Markdown for Agents 的站，智能体请求 Markdown 时能在 YAML 前言里看到同样信息。

Cloudflare 自己的开发者文档已经先用上了。官方演示里，OpenCode 会话问了一句 Artifacts 的推送上限，智能体先在首页发现搜索接口，再调 /.well-known/search 拿回结果，几秒后给出正确答案。演示用的是真实文档，不是摆拍的幻灯片。

新 HTTP 方法 QUERY 也搭了进来。它是今年6月发布的 RFC 10008，允许把查询条件放在请求体里，又不改服务器状态。Cloudflare 自己的 James Snell 是这份标准的合著者之一。curl 与 undici 已经在跟进，浏览器厂商也在讨论。

01 / WHAT TO WATCH

免费版也能开，但账单从12月开始算

所有套餐都能开，包括免费版，额度有限。费用按 AI Search 的标准收，内容摄入、索引存储与查询都算钱，免费版额度用完就停，付费版超量另计。

默认配置值得先看一眼。索引更新需要时间，子域名默认不在爬取范围里。文档站与客服站分开部署的，先核对索引里到底装了什么，再决定开给谁。

02 / WHY IT MATTERS

给智能体开门，先想好门后有什么

搜索入口一旦公开，任何能访问的智能体都能查。站长现有的机器人管理与防火墙规则仍然生效，敏感内容要先挡在索引之外。

这一步的意义在规模。Cloudflare 替站长省掉了自建检索系统，网站向智能体开放的门槛从工程活降到了开关。门一开，智能体找到资料的速度与质量，就看各家索引的成色。

// DETERMINISTIC EXECUTION PIPELINE

01 / THE OLD WAY

以前要让智能体搜网站，得手动建 AI Search 实例、配集成、再想办法让智能体发现接口。

02 / THE TOGGLE

11月25日，Cloudflare 把这套流程收到一个开关后面。打开开关，服务自动建实例、爬内容、建索引。

03 / THE ENDPOINT

搜索接口挂在网站自己的域名下，路径是 /.well-known/search。智能体用关键词或自然语言提问，拿到带来源与相关度分数的 Markdown 片段。

04 / THE GUARDRAILS

接口照样受站长的机器人管理、AI 爬取控制与防火墙规则约束。想让智能体搜到什么，先看清索引里装了什么。

03 / PARADIGM SHIFT

从爬完整站，到直接问一句

FROM CRAWLING EVERY PAGE TO ASKING ONE QUESTION

从爬完整站，到直接问一句

过去智能体找资料要逐页爬。网站现在直接给一个搜索接口，智能体问一句，拿回相关片段。

FROM GENERATED ANSWERS TO RETRIEVED PASSAGES

从返回答案，到只返回原文

接口只返回网站原文的 Markdown 片段，不替智能体作答。解读与引用归智能体自己的模型，错了也赖不到网站头上。

BOUNDARY / 边界与工程约束

功能处于测试阶段，索引更新需要时间，返回内容不一定是最新版。接口只返回原文片段，不保证智能体解读正确或引用准确。费用按 AI Search 计价，免费版有额度上限。
