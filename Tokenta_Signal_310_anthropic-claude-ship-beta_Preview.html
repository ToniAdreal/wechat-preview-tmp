CASE STUDY / 案例分析

11月23日，Anthropic 在官方博客宣布 Claude Ship 进入测试版。Code Review 早已全面可用，PR Steward 与 Claude Approvals 是新加入的测试版智能体。分工明确，一个审，一个修，一个按规矩批。

Code Review 对照整个代码库做多角度审查，结论先自我验证再分类贴回 PR。Anthropic 自己的 Claude Code 团队是第一个吃螃蟹的人，6 月到 9 月，合并的 PR 数量翻了一倍多，被回滚的比例降了四成以上。PR Steward 接手后面的脏活，CI 挂了、合并冲突了、评审意见没处理，它都去修，每推一次就留言写清改了什么、怎么撤销。它不批也不合并。

Claude Approvals 是变化最大的那一步。它读团队写在仓库里的审批 policy 文件，像一份更聪明的 CODEOWNERS，常规改动自己批，高风险的交还给人。Anthropic 建议先开观察模式跑一段时间，建立信任后再把分支保护交给它。开发者也可以在 Claude Code 里敲 /ship，从推代码、开 PR 到走完评审，全程不用手动接力。

01 / WHY IT MATTERS

先观察再放权，是这套产品最诚实的设计

Anthropic 没有把 Approvals 吹成开箱即用的自动合并。它在文档里写明，建议先跑观察模式，等团队看清它在什么情况下放行、什么情况下拦下，再决定要不要把它写进分支保护。信任要靠跑出来的记录建立。

这个顺序也划清了责任边界。policy 文件是团队自己写的，模型只是在文件划定的范围里执行。出问题时，复盘先看文件写得对不对，再看模型执行得怎么样。责任没有消失，只是从每次评审的人，挪到了写规则的人身上。

02 / WHAT TO WATCH

按 token 计费，评审越勤账单越厚

Claude Ship 按 token 收费，审得越深、修得越多，账单越高。管理员可以给 Code Review 与 PR Steward 设支出上限，Approvals 本身不收基础费，但 policy 里调用的分类器要按 token 算钱。符合条件的 Enterprise 组织能领至少 1 万美元 credit，2027 年 1 月 15 日前申领，领到后 30 天内用完。

门槛也划得很清楚。零数据保留、HIPAA 配置与客户自管加密密钥的组织用不了，GitHub 之外也不支持。Anthropic 先把这套能力锁在 Team 与 Enterprise 的 GitHub 仓库里，等于先收最付得起钱、也最需要这套流程的那批团队。

// DETERMINISTIC EXECUTION PIPELINE

01 / THE LAUNCH

Anthropic 发布 Claude Ship 测试版，三款智能体覆盖 PR 全流程。

02 / THE REVIEW

Code Review 多角度审查 PR，结论自我验证后分类贴回。

03 / THE FIX

PR Steward 修 CI、解冲突、处理评审意见，每次推送都留言交代。

04 / THE APPROVAL

Claude Approvals 按仓库里的 policy 文件批常规改动，高风险的交给人。

03 / PARADIGM SHIFT

从写代码，到管合并

FROM WRITING CODE TO DECIDING MERGES

从写代码，到决定什么能合并

智能体先是帮人写代码，现在开始参与决定哪些代码进主分支。评审这道关，从人力排队变成 policy 文件说了算。

FROM PER-REVIEW APPROVAL TO POLICY FIRST

从每次人工拍板，到先写规则再执行

审批权先写成文件，再由模型按 PR 执行。团队的治理能力，变成写 policy 的能力。

BOUNDARY / 边界与工程约束

测试版范围有限：只支持 GitHub 仓库，只面向 Team 与 Enterprise 计划，零数据保留、HIPAA 配置与客户自管加密密钥的组织不在覆盖内。Anthropic 自家团队的合并量与回滚率是厂商自己的说法，未经独立验证。按 token 计费，实际成本随 PR 数量与审查深度浮动。
