CASE STUDY / 案例分析

“Anthropic 正在把文本水印扩展到四款模型，Mythos 5、Opus 4.7、Opus 4.6 与 Sonnet 4.6。2026 年 8 月 2 日之后发布的模型出厂即带水印，老模型分批补上，这次补的是其中四款，背景是欧盟 AI 法案 12 月的透明度期限。”

“水印的原理，是在选词的随机性里织入肉眼看不见的统计模式。Anthropic 的说法是，它不增加字符与 token，不改变价格与请求格式，不改变含义、质量与可读性，客户也不能直接关掉它。”

“漏洞出在两款老模型上。Opus 4.6 与 Sonnet 4.6 只有在 temperature、top_p、top_k 三个采样参数全部保持默认值时才打标，改动其中任何一个，哪怕只改一点点，输出就没有水印。”

权威信源佐证 · The Decoder 报道　查看原文 ↗

佐证解析：原文确认 Anthropic 把水印扩展到 Mythos 5、Opus 4.7、Opus 4.6 与 Sonnet 4.6，其中 Opus 4.6 与 Sonnet 4.6 只有采样参数保持默认值时才打标，改动一个参数即可绕过。

01 / ONE DIAL

“一个参数，就能绕过合规标记”

“采样参数控制模型选词时的随机程度，是开发者每天都会调的东西。温度调高一点，输出更发散，温度调低一点，输出更稳定，这都是正常用法。结果在两款老模型上，正常调参顺带就把水印调没了。”

“Anthropic 在邮件里把话说得很直白，依赖水印做合规的客户，请把这三个参数留在默认值。这等于把合规责任推回给调用方，标记本身不再是无条件的保证。”

02 / THE DISCOUNT

“水印的承诺，正在被现实打折”

“水印技术来自谷歌 DeepMind 的 SynthID 文本方法，思路是在随机性里留痕。思路成立的前提，是随机过程按预期走。一旦开发者改了采样参数，随机过程变了，痕迹的统计基础也跟着变。”

“这也是为什么新模型与老模型要分开看。Opus 5.5 及更新的模型已经带标，邮件没有给它们加同样的限制。老模型的补标更像赶期限的工程折中，先覆盖，再谈无条件。”

03 / ASK VERSION FIRST

“合规方真正该问的，是版本与参数”

“对任何依赖水印做合规的团队，检查清单现在多了一行。先确认跑的是哪款模型，再确认 temperature、top_p、top_k 是不是默认值，两个条件缺一个，输出的标记状态就不能默认成立。”

“更稳妥的做法，是直接换到更新的模型，或者在调用层把三个参数锁死。水印检测 API 还在私人预览，事后检测补不上事前没打标的缺口。”
